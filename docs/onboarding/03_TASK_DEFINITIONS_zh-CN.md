# 任务定义、数据合同与验收标准

[返回学习路线](README.md) · [上一篇：项目逻辑](02_PROJECT_LOGIC_zh-CN.md) · [术语速查](04_GLOSSARY_zh-CN.md)

本篇把研究目标写成可以实现、检查和交付的任务。前两节概括保留的历史任务，
其余章节重点说明当前 Round 11。输入、标签、输出和评价必须成套理解，不能跨任务混用。

## 1. 任务 S：给定条件，预测分布快照

数学映射为 `S_theta(k, alpha, t) -> normalized_delta_f(x,v,t)`。
模型另外使用相空间坐标；输出是一个完整网格场，不是一个阻尼率或能量标量。

| 项目 | 定义 |
|---|---|
| 输入 | 初始参数、查询时间和模型所需坐标 |
| 标签 | 历史精确抽样 PIC 缓存中的归一化分布扰动 |
| 输出 | 单时刻相空间场；对应旧正式网格 `128 x 193` |
| 推理特点 | 可以直接查询时间，不要求先生成之前的每一帧 |
| 评价 | 分布相对误差、密度与电场等派生量、完整 `f` 的负值情况 |
| 范围 | 旧正式模型主要验证 `t=0..15`；不能据此声明长时间或新数据族准确 |

归一化使用训练集估计的背景与尺度。`mean_delta` 表示扰动的空间零模，
不是速度积分后的密度第一模。实现与限制见[方法说明](../science/METHOD.md)和
[训练流程](../operations/TRAINING_PIPELINE.md)。

## 2. 任务 R 和 M：预测下一状态

**旧分布 Stepper**：输入当前归一化 `delta_f` 和条件，预测 `t+0.5` 的分布。
单步训练可能输入真实当前帧，自由 rollout 则递归输入自己的预测。
旧最终模型的空间平均锚定方式与 positivity 约束见相应 checkpoint 和方法说明。

**Round 10 宏步代理**：状态为 `U_raw=[M0,M1,M2,E]`，模型输入有限历史及
`K,alpha,DeltaT` 条件，输出 `U_raw(t+DeltaT)-U_raw(t)`。
它学习状态增量，并包含该轮规定的投影与评价；不输出瞬时热流梯度。
历史长度、宏步大小和真值初始化范围应按[Round 10 协议](../experiments/LANDAU_MACROSTEP_ROUND10_PROTOCOL_zh-CN.md)
及实际配置核对，不能套用下面的 Round 11 参数。

## 3. 当前任务 C：用历史低阶场预测瞬时闭合

固定当前状态与目标：

$$
U(x,t)=[n,u,p,E](x,t),\qquad g(x,t)=\partial_xq(x,t).
$$

设历史时间偏移为 `a_j`，有效性标记为 `b_j`。模型映射为：

$$
\widehat g(t)=C_\theta\left(\{U(t-a_j),b_j\}_{j=0}^{7},K,[\alpha]\right).
$$

`[alpha]` 表示可选输入，不是每个 arm 都启用。目标 `g` 与最后一个历史槽处于同一时刻。
模型预测的是**当前方程右端需要的闭合项**，下一状态由 RK4 与流体方程计算。

### 3.1 数据接口与形状

这里 `B` 表示一批训练样本数，`Ncase` 表示案例数，`Nt` 表示时间点数，`Nx` 表示空间网格点数。
一个 case 是一组初始条件下的一整条轨迹，frame 是其中一个时间切片。

| 阶段 | 内容 | 形状 / 通道顺序 |
|---|---|---|
| HDF5 原始读取 | `diagnostics/central_moments` | `[Nt,Nx,4]`，通道 `[n,u,T,q]` |
| 适配后的低阶场 | `ContinuumTrajectory.state` | `[Nt,3,Nx]`，通道 `[n,u,p]`，`p=n*T` |
| 适配后的标签 | `heat_flux_gradient` | `[Nt,Nx]`，从 `q` 按物理空间尺度求导 |
| 统一时间缓存 | `HistoryCache.state` | `[Ncase,Nt,4,Nx]`，通道 `[n,u,p,E]` |
| 一批网络输入 | `history` | `[B,8,4,Nx]` |
| 历史标记 | `valid` | `[B,8]`，布尔值 |
| 案例条件 | `k`、`alpha` | 各为 `[B]`；A/B 的 alpha 输入通道被置零 |
| 模型输出 | `gradient` | `[B,Nx]`，恢复了目标物理尺度的 `dq/dx` |
| 完整验证保存 | `prediction`、`truth` | `[Nout,Ncase,4,Nx]`；当前 `0..80`、输出间隔 `0.1` 时 `Nout=801` |

轴顺序在缓存、网络与保存文件之间确实不同。不要只看数组里有“四个通道”就直接传递。
网络内部会先做训练集归一化，外部接口仍接收未做机器学习标准化的无量纲物理场。

### 3.2 数据集和划分

Round 11 协议使用通过冻结 QC 的 `continuum_v1` 案例：

| 划分 | 案例数 | 允许用途 |
|---|---:|---|
| train | 139 | 梯度训练、训练统计量、训练窗口 |
| validation | 20 | 历史跨度选择、模型选择、质量门、冻结前计时选择 |
| 既有 diagnostic test | 36 | 既往已经打开的开发诊断集；不再称为全新盲测 |
| 新独立 holdout | 配置准备了 12 组新参数 | 在模型、阈值和生成配置冻结后，才生成参考并做最终评价 |

这是**按案例划分**，不是把同一条轨迹的相邻帧随机分散到三种集合。
新 holdout 的“12”是准备的参数数目，不是已通过验证的成功案例数。
参数列表见[holdout 配置](../../configs/gkeyll/continuum_round11_holdout.json)。

输入均值、标准差以及 `K/alpha/g` 的尺度只由训练集确定，验证与部署复用这些值。
不要在每个验证案例上重新归一化，也不要把 test 纳入统计量计算。
实际文件还需通过 dataset version、case ID、参数、时间单调性、正性等接口检查。

### 3.3 八个历史槽是什么

给定历史跨度 `H`，槽位顺序从较早到当前：

```text
age/H = [1, 0.75, 0.5, 0.25, 0.125, 0.0625, 0.03125, 0]
```

例如 `H=2`、当前 `t=3`，对应查询时刻：

```text
[1, 1.5, 2, 2.5, 2.75, 2.875, 2.9375, 3]
```

它们不是连续八帧，也不是八个等间隔时间点。查询依据物理时间插值；
原始 Gkeyll 输出触发时刻可能有轻微偏差，不能靠帧编号假定时间严格一致。

若查询时刻小于 0，用初态填充，并标记 `valid=False`。在 `H>0,t=0` 时，
八个状态槽的值相同，但只有当前槽有效。训练样本显式覆盖这个边界。
自主推进的后续历史由接受的预测状态维护，中间 RK 状态不会成为未来真值的入口。

### 3.4 A/B/C 的精确定义

| arm | 状态信息 | K | alpha 作为网络输入 | 对照方式 |
|---|---|---|---|---|
| A | `H=0`，当前状态重复八次 | 启用 | 不启用 | 瞬时基线 |
| B | 八槽历史，正式冻结跨度为 2 | 启用 | 不启用 | 与 A 比较历史的作用 |
| C | 与 B 相同的历史 | 启用 | 启用 | 与 B 比较初始幅度标签的作用 |

每槽四个场加一个标记，共 `8*5=40` 个通道，再加 alpha 槽和 K 槽，
进入 FNO 的特征通道总数为 42；A/B 的 alpha 槽为零。
三组由此保持相同的输入大小与主干配置。所有组都不输入绝对时间。
`alpha` 仍可用于数据索引和统一的损失尺度；“A/B 不输入 alpha”不等于整个训练程序完全不读取它。

### 3.5 输出与数值约束

当前正式 overrides 保留 `maximum_mode=16`、反射等变性，并相对未滤波矩场评价。
网络输出只保留 `1..16` 的非零空间模态，零模和更高模态被去掉。
内部 FNO 的模态数量是 `maximum_mode+1=17`，其中包括零模槽；不要混淆这两个配置含义。

反射映射下 `n,p` 为标量，`u,E` 变号，`g=dq/dx` 为标量。
实现对原输入与反射输入做成批预测并组合，开销必须纳入计时；
这个约束不等于把任意输入都强制修改成一个对称初态。

## 4. 训练、诊断和部署的信息边界

| 场景 | 可以读取什么 | 不能用来宣称什么 |
|---|---|---|
| Oracle 数值审计 | 参考初态、各时刻参考 `g`，以及用于对比的参考矩场 | 不能称为自主神经预测或闭合学习成功 |
| 监督训练 | train 的真实历史与同一时刻标签 | 不能把真实历史上的误差当作自由演化误差 |
| 多步训练 | train 的起始状态/历史、用作损失的参考未来 | 不能把损失用到未来标签说成部署可读取未来 |
| 短窗 validation | validation 的参考起点、窗口目标，预测过程自主推进 | 不能替代从初态开始的完整轨迹评价 |
| 正式自由 validation / holdout | 初态、已知参数、模型自己生成的历史；真值在外部打分 | 不能每一步重置为真值、注入真实热流或未来历史 |

关键区别是：**真值作为打分标签**不等于**真值参与了生成预测**。
正式验证从 `t=0` 初始化，未来参考帧即使被移除，预测本身也应保持不变。

## 5. 训练目标与正式配置

监督阶段最小化归一化闭合误差，大意为：

$$
L_g=\operatorname{mean}\left[(\widehat g-g^*)^2/\sigma_g^2\right].
$$

星号表示参考值，`sigma_g` 来自训练集。多步阶段的损失组成见
[trajectory_losses](../../src/landau_surrogate/training/continuum_history_closure.py)：

| 项 | 约束对象 | 为什么需要 |
|---|---|---|
| state | 按扰动尺度衡量的 `n,u,p,E` 误差 | 避免大背景掩盖小但重要的波动 |
| complex_field | 电场前四个非零复模 | 同时约束振幅与相位 |
| log_energy | 带数值地板的 log10 场能 | 关注跨数量级衰减与反弹 |
| supervised | 起始采样状态上的闭合标签 | 保留参考状态上的闭合监督 |
| conservation | 总能量、质量与动量的变化 | 抑制整体漂移 |
| positivity | 接近不安全密度/压力区域的软惩罚 | 训练中提前对不良状态施压 |

训练的 positivity 项在 `n<0.3`、`p<0.15` 时已有软惩罚，
它不是正式验证的物理失败线；正式验证要求所有受检查状态 `n>0,p>0` 且有限。
当前 Round 11 右端使用 `density_floor=None`，不把负密度或负压力钳回可用值。

| 参数 | pilot 模板 | 控制器生成的正式设置 |
|---|---|---|
| FNO | width 128，4 层 | 相同主干 |
| 监督阶段 | 8 epochs，每 case 256 次采样 | 20 epochs，每 case 512 次采样 |
| 有梯度窗口 | 物理时长 0.2、1、2，各 1 epoch | 0.2 持续 3 epochs；1 和 2 各 4 epochs |
| burn-in | 自主刷新 5 个时间单位，无梯度 | 同样刷新，再开始完整有梯度窗口 |
| 流体步长 | 0.02，需通过 oracle 门 | 0.02，与冻结数值门一致 |
| 历史 | B 探索 0.5/2/5，C 用选定跨度 | B/C 冻结为 2；A 为 0 |
| 随机性 | pilot seed 0 | 每 arm 的 seeds 0/1/2 |

正式配置来自[流水线控制器](../../scripts/run_round11_closure_pipeline.py)与
[formal_overrides.json](../../results/continuum_v1_closure_round11/formal_overrides.json)，
不能仅凭 pilot 文件复现正式实验。三个种子共享既有监督初始化，主要改变采样随机性。
完整有梯度窗口内不 detach；梯度检查点通过重算中间值节省显存，和保存模型的 checkpoint 文件是两回事。

## 6. 完整评价具体比较什么

### 6.1 首先检查是否完成

当前全程为 `t=0..80`，保存间隔为 `0.1`。检查覆盖滤波后的 RK 中间状态及接受状态。
任一状态非有限，或出现 `n<=0`、`p<=0`，都要记录首次失败时刻。
保存用于评价的轨迹在失败之后标为缺失；不能仅在较短的成功前缀上计算误差，再声称完成全程任务。

### 6.2 场能、扰动和相位分别回答什么

当前场能用 `W_E=0.5*mean_x(E^2)`，log10-RMSE 衡量预测和参考场能的对数差。
取对数前设置地板，避免接近零的场能造成无意义的无穷大；它是指标处理，不是修改物理轨迹。
固定的 log10 差 0.3 大致对应能量相差两倍，但“RMSE=0.3”不表示所有帧都恰好差两倍。

令 `Ueq=[1,0,1,0]`，扰动相对 L2 在指定时间区间按当前实现计算：

$$
e_{\mathrm{pert}}=\frac{\|\widehat U-U^*\|_2}
{\max(\|U^*-U_{eq}\|_2,10^{-12})}.
$$

它使用四个无量纲物理通道的联合范数，**不是**先给每个通道除以训练标准差。
训练 state loss 的尺度与这个报告指标不同。评价中减去平衡态的目的是显式衡量扰动，
避免“背景为 1，预测为 1”掩盖模型对小幅波动的失真。

相位指标用电场第一复模：`abs(arg(Ehat_pred * conj(Ehat_truth)))`，单位为弧度。
在全程参考第一模最大振幅的基础上，晚期汇总只保留超过 `max(Amax*1e-4,1e-12)` 的参考帧。
在参考信号有效但预测振幅不超过 `max(Amax*1e-6,1e-14)` 时，
当前实现将其相位误差计为 `pi`，并记录缺失预测相位的帧数；不会把无信号当成零误差。
没有有效参考信号时，相位指标为空，而不是自动通过。

这些晚期汇总定义以
[interval_metrics](../../scripts/summarize_round11_history.py)为准。
全程报告、晚期报告的时间掩码不同，读结果时必须同时看指标名和区间。

### 6.3 当前正式质量门

以下是本轮冻结的**工程验收线**，不是 Landau 阻尼的普遍物理定律，也不是跨实验通用标准。
准确值保存在[quality.json](../../configs/training/continuum_history_closure_round11_quality.json)。

| 检查 | 当前阈值 | 聚合范围 |
|---|---:|---|
| 有效完成比例 | 1.0 | 每次运行的所有 validation 案例 |
| 总能量最大相对漂移 | 不超过 0.001 | 每个案例均检查 |
| 质量平均值最大绝对漂移 | 不超过 0.0001 | 每个案例均检查 |
| 动量平均值最大绝对漂移 | 不超过 0.0001 | 每个案例均检查 |
| 晚期场能 log10-RMSE | 中位数不超过 0.3 | `t=30..80` 的逐案例指标 |
| 晚期电场第一模相位 MAE | 中位数不超过 0.35 rad | 同一晚期区间的有效信号帧 |
| 晚期扰动相对 L2 | 中位数不超过 0.25 | 同一晚期区间 |
| 各物理类别的晚期场能误差 | 每类中位数不超过 0.5 | weak / transition / strong_nonlinear 分别检查 |
| 正式随机种子 | 0、1、2 均通过 | 同一 arm 才能进入加速候选阶段 |

“20 个案例中完成 15 个”的模型，不会因为剩下 15 个的平均误差较小而通过。
上述精度门也没有要求三种子互相比较后只挑最好的一次。

### 6.4 公平比较两个模型

先报告两者各自完成多少案例。比较误差差值时，使用**双方共同完成的相同案例**和相同时间区间。
分别比较两个不同幸存集合的中位数，会把“失败掉最困难案例”误判为提高了精度。
原始 pilot 与增加反射等变性的正式配置也应分开标记。

## 7. 加速和盲测任务怎样定义

进入加速阶段的前提是至少一组正式 arm 的三个种子全部通过质量门。
随后尝试降低闭合更新频率、缩小网络宽度并重训；这些都是新候选，需要再次验证。

相对基准，候选的三项晚期误差须满足当前约定的“不恶化超过 10%”，另加 `1e-4` 绝对容差，
同时满足原质量门。低频闭合的更新间隔与流体步长不同：
流体仍可每 `0.02` 推进一步，闭合值可以按更长间隔更新并在期间保持。

计时要写清楚：硬件型号与占用、批量、时间终点、矩场输出间隔、
是否含加载、传输、写盘，以及参考求解器的计时范围。
共享设备计时是观测结果，不是独占硬件严格基准。
参考输出的内容也要一致，不能把“只输出矩”的模型等同于“恢复完整分布”。

在已有 validation 上完成候选选择和计时后，保存模型、阈值、生成配置与源码哈希，
再生成新 holdout 的动力学参考。参考先经过 QC，再评估冻结模型。
看到 holdout 失败后修改模型并重报同一集合，便不再是原来的独立盲测。
若正式质量门失败，控制器应记录负结果并停止于精度门，而不是继续生成盲测数据。

## 8. 哪些情况不在当前任务的保证范围内

- 当前闭合不输出完整速度分布；矩场准确不证明相空间细节准确。
- 当前初态族与固定背景模型，不等同于任意初始分布、多物种、碰撞或磁化问题。
- 对 `K/alpha` 范围内的插值表现，不等同于范围外的外推表现。
- `t=80` 的结果，不等同于任意更长时间稳定、准确。
- 当前数据、步长和频带的结论，不自动延伸到其他分辨率或另一种求解器。
- 软件测试通过证明受测实现行为正确，不证明研究假设成立。

要扩大这些范围，应定义新的数据合同、对照、评价区间和验证预算。

## 9. 一次实验需要交付什么

| 交付物 | 最低内容 |
|---|---|
| 问题说明 | 研究问题、基线、只改变的因素、预期证据 |
| 可复现配置 | 完整 CLI、实际 config、随机种子、代码 commit/源码哈希 |
| 数据来源 | dataset version、case IDs、split、标签与归一化定义 |
| 模型 | checkpoint 及其对应配置、训练记录、选择依据 |
| 预测结果 | 完整矩场、电场、闭合、时间坐标、案例标识 |
| 失败记录 | 是否完成、最早失败时刻、最小密度/压力、非有限性 |
| 数值报告 | 全程与晚期误差、逐案例指标、共同完成集合、守恒漂移 |
| 性能报告 | 网络调用次数、计时范围、硬件和可比较的基准 |
| 结论 | 支持的结论、未解决问题、失败结果和下一项可检验假设 |

代码、配置与解释性文档提交 Git；数据、权重、完整轨迹和生成图片放到共享资产目录。
所有新输出使用个人独立的运行目录，不能覆盖既有冻结结果。

## 10. 把研究问题写成可执行的小任务

不要只写“提高模型效果”。可用下面的模板：

```text
问题：要检验哪个具体行为或假设？
基线：使用哪个 commit、数据划分、模型和配置？
输入与输出：读取哪些字段，生成什么可检查的产物？
改动：只改变什么，其余哪些条件保持一致？
验证：使用什么案例、区间、指标，怎样判定通过或失败？
资源：使用哪个个人目录，CPU/GPU 预算和停止条件是什么？
结论边界：通过后能说明什么，仍然不能说明什么？
```

### 示例 A：入门的数据合同核对

问题：确认某条 validation 轨迹的温度、压力与热流字段没有混用。
只读加载一个 case，记录元数据和数组形状，验证 `p=nT`、时间严格递增、
以及周期 `dq/dx` 的空间平均接近零。交付字段表、检查命令和容差依据。
它验证数据接口，不证明神经闭合准确；无需启动训练或读取新 holdout。

### 示例 B：一个已有闭环失败案例的诊断

使用已有冻结 checkpoint 和同一 validation 案例，记录最早的异常时刻，
同时查看电场模态、压力、闭合频谱和守恒。先判断异常出现在已接受状态还是 RK 中间状态。
交付可重复命令和按时间对齐的证据；不能只凭一张末帧图断言网络结构必然错误。

### 示例 C：有明确控制变量的研究实验

检验“在相同模型、初始化与预算下，延长有梯度窗口是否改善晚期误差”。
先在现有 train/validation 设计小规模对照，冻结要改的唯一因素，
报告相同案例上的完成率与三项晚期指标；暂不打开新的独立 holdout。
这是后续任务示例，不表示本教程已经批准或启动这项训练。
